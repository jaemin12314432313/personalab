PersonaLab 디자인 로드맵과 워크스페이스 홈 시안 6종

화면 명세를 읽고, 어떤 순서로 어떤 화면을 몇 가지 방향으로 만들지 정리했습니다. 첫 번째 대상은 워크스페이스 홈입니다. 시안의 이름·수치는 모두 예시입니다.

먼저 정할 것로드맵화면별 시안 계획워크스페이스 홈 시안고르는 기준

시안 전에 맞춰야 할 충돌 2가지

1. 단위가 ‘프로젝트’인가 ‘테스트’인가

기억해 둔 확정안(c10)은 프로젝트 단위 홈입니다. 새 명세는 프로젝트 계층을 강제하지 않고, 같은 테스트를 여러 회차로 반복하게 합니다. 이번 시안은 명세를 따라 ‘테스트 + 최신 회차 대표’로 그렸습니다. 프로젝트로 가려면 상위 묶음 한 단계가 늘어나므로 선택이 필요합니다.

2. 사이드바

명세의 홈 구성은 사이드바를 포함하지만, 이전에 사이드바가 별로라고 하셨습니다. 시안 B만 사이드바이고 나머지는 상단 메뉴입니다. 상단 메뉴가 되면 명세의 메뉴 3개(내 테스트, 페르소나 보관함, 전체 실행 기록)는 그대로 유지됩니다.

로드맵

명세 16장의 우선순위(흐름의 모호함 해결 → 끝까지 쓰는 경험 → 공개 운영)를 따르되, 맨 앞에 토대 작업을 두고 워크스페이스 홈부터 시작합니다. 기간은 한 사람이 시안을 만들고 검수하는 기준의 추정치입니다.

0단계1~2일

결정 정리와 토큰 고정

  • 프로젝트/테스트 단위, 사이드바 유무 결정
  • c10 Greige 팔레트와 랜딩 글꼴(세리프 제목·산세리프 본문)을 토큰 파일로 고정
  • 상태 6종(작성 중·실행 준비 완료·실행 중·완료·중단·부분 기록)의 이름, 색, 버튼 문구 표 확정

끝났다는 기준: 상태→문구→버튼 표 한 장이 승인되고, 이후 모든 시안이 이 표를 씁니다.

1단계3~5일

워크스페이스 홈 (이 문서의 시안)

  • 시안 6종 비교 → 1종 선택 → 선택안의 빈 상태·검색 결과 없음·서버 연결 실패·로딩 상태까지 완성
  • 관리 메뉴(이름 변경·복제·수정 회차·보관·휴지통·회차 이력)의 위치와 적용 범위 문구
  • 공통 부품 추출: 앱 셸, 상태 표시, 상태별 버튼, 목록 행

끝났다는 기준: 6개 상태 모두에서 한 번의 클릭으로 올바른 화면에 도착하고, 개요 화면을 거치지 않습니다.

2단계1~2주

1순위: 실행과 3D 관찰, 실행 이후 행동

  • 실행 중·기록 재생·중단·완료·기록 없음 5가지 상태의 제목과 주요 버튼 분리
  • 사람 전환(좌우)과 화면 이동 경로(아래)를 분리한 조작
  • 작성용 ‘이전·다음’ 막대를 ‘결과 보기·부분 기록 보기·설정 수정’으로 교체

끝났다는 기준: 화면을 보고 지금 진행 중인지, 왜 멈췄는지, 누가 어느 화면인지, 다음 행동이 무엇인지 답할 수 있습니다.

3단계1~2주

2순위: 끝까지 쓰는 경험

  • 리포트: 발견 목록과 근거 화면, 부분 기록 표시, 확인 범위 탭
  • 1대1 인터뷰: 기록 모드와 AI 대화 모드 구분, 근거 열기
  • 수정 회차 만들기와 두 회차 비교

끝났다는 기준: 발견 하나에서 근거 화면, 해당 페르소나 인터뷰, 수정 회차까지 막힘없이 이어집니다.

4단계1주

새 테스트 설정 6단계 정리

  • 단계 표시줄과 이전·다음 공통화, 단계마다 한 가지 일만 남기기
  • 기술 정보(DOM, 요청 차단)를 상세 탭으로 이동
5단계1주

3순위: 랜딩 정합성, 가입·로그인, 공개 샘플, 운영 상태

  • 기능 범위와 문구 일치 점검, 공개 샘플의 출처 표시
  • 사용량·결제·팀 기능은 실제로 만든 뒤에만 노출
상시매 단계 끝

검수

  • 명세 16장 체크리스트 18개 중 해당 항목 확인
  • 1280·1024·390px 폭, 키보드 이동, 모션 감소, 확대 보기에서 실제 렌더링 확인 후 ‘시각 검수 완료’ 기록

화면별로 몇 가지 시안을 만들까

방향이 갈리는 화면에만 시안을 여러 개 만듭니다. 나머지는 1~2개로 충분합니다.

워크스페이스 홈 시안 6종

같은 예시 데이터 6건(상태 6종을 하나씩)을 다른 구조로 배치했습니다. 모두 명세의 필수 요소를 갖췄습니다: 검색·상태 필터·정렬, 상단 도구 영역의 새 테스트 버튼, 최신 회차 대표 표시, 상태에 맞는 버튼, ⋯ 메뉴. 인사말, 종합 점수, 엽서형 카드는 넣지 않았습니다. 시안은 정지 화면입니다.

공통 상태빈 워크스페이스와 검색 결과 없음 (모든 시안 공통)

명세 6장: 첫 가입 직후에는 문장 하나와 버튼 하나만 보여 줍니다. 가짜 프로젝트는 채우지 않습니다.

고르는 기준과 추천

  • 가장 안전한 선택: 시안 A. 확정했던 c10과 랜딩 포커스 구조를 이어받아 달라지는 부분이 용어(프로젝트→테스트)뿐입니다.
  • 테스트가 10개 이상 쌓일 때 유리한 선택: 시안 B(표)나 D(할 일 순서). 이어서 할 일을 찾는 시간이 줄어듭니다.
  • 캡처를 보고 제품을 기억하는 사용자에게 유리한 선택: 시안 E. 다만 명세가 말한 ‘정보 밀도’는 가장 낮습니다.
  • 수정 회차를 자주 돌릴 때 유리한 선택: 시안 F. 회차 이력이 홈에서 바로 보입니다.
  • 제 추천: A를 기본 틀로 쓰고, 테스트가 6개를 넘으면 목록 아래쪽이 D처럼 ‘확인할 것 / 이어서 할 것 / 결과 본 것’으로 묶이게 하는 조합. 히어로가 하나뿐이라 사용자가 먼저 볼 것이 분명합니다.

마음에 드는 시안 하나(또는 조합)를 알려 주시면 1단계로 넘어가 상태별 화면과 부품까지 완성하겠습니다. 실제 앱(frontend/src/mockup)에는 아직 옮기지 않았습니다.
