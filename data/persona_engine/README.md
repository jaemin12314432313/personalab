# Persona Engine 사용 안내

조건(예: "20대 대학생 100명")을 넣으면 **AI 페르소나 카드**를 만들어 주는 도구입니다.
만든 카드는 Ask·Act 모드에서 AI에게 "너는 이런 사람이다"라고 알려 주는 데 씁니다.

- 카드 미리보기: [PersonaLab 카드 뷰어](https://claude.ai/artifact/SCYLzfPF6TJKnbRjoi7Q1t) (공유받은 팀원만 열림)
- 실행 파일: `scripts/make_panel.py` 하나만 기억하면 됩니다

---

## 1. 이게 뭔지 30초 설명

```
NVIDIA 한국인 페르소나 100만 명      →  "누구인가"  (나이, 직업, 사는 곳, 성격, 취미)
한국미디어패널 2024 실제 응답자 8,693명 →  "돈과 앱을 어떻게 쓰나" (OTT 결제, 가격 민감도, 앱 적응, 개인정보 반응)
                    ↓
     둘을 짝지어 페르소나 카드 한 장 = 한 사람
```

NVIDIA 데이터만 쓰면 AI가 가격 질문에 엉뚱하게 답합니다(소득·구독 정보가 없어서). 그래서 조건이 같은
**실제 조사 응답자 한 명의 소비 습관**을 붙입니다. 모델 학습은 없습니다.

카드 예시:

```
21세 남자 대학생이고 광주 지역에 산다.                       ← 프로필 (NVIDIA)
김재연 씨는 광주 남구의 ... 사교적인 20대 청년입니다.          ← 성격·취미 서술 (NVIDIA)
주말이면 친구들과 모여 LCK 경기를 시청하며 ...
OTT는 가족 계정을 쓰고 본인은 내지 않는다.                    ← 행동 문장 (실제 응답자)
꼭 필요한 서비스에만 돈을 낸다.
새 앱에 금방 익숙해지고 사용법을 따로 찾아보지 않는다.
가입할 때 개인정보를 입력하는 것에 크게 신경 쓰지 않는다.
```

행동 문장에는 일부러 숫자(금액, 점수)를 넣지 않습니다. 숫자가 있으면 AI의 가격 응답이 그 숫자로 쏠립니다.

## 2. 처음 한 번만 준비

1. 저장소를 받고 이 폴더로 이동
   ```
   git checkout main && git pull
   cd data/persona_engine
   ```
2. **원본 데이터 넣기** (git에 없음, 팀 공유 폴더에서 받기)
   `원시자료 데이터_20260925.zip`, `코드북_유저가이드_20260925.zip`을 저장소의 `data/raw/`에 풀어 둡니다.
   `data/raw/p24v32_KMP_spss.sav`, `data/raw/P_codebook_v32.xlsx`가 보이면 성공입니다.
3. 설치 (Windows)
   ```
   python -m venv .venv
   .venv\Scripts\activate
   pip install -r requirements.txt
   ```
4. 한글 깨짐 방지: 터미널을 열 때마다 `set PYTHONUTF8=1`

처음 실행할 때 NVIDIA 데이터(약 2GB)를 자동으로 받습니다. 1~2분 걸리고, 그다음부터는 몇십 초면 끝납니다.

## 3. 페르소나 만들기 (예시 모음)

터미널에서 `data/persona_engine` 폴더에 있는 상태로 실행합니다.

| 하고 싶은 것 | 명령어 |
|---|---|
| 20대 대학생 100명 (기본) | `python scripts/make_panel.py --preset univ` |
| 30대 사무직 50명 | `python scripts/make_panel.py --preset 30s_office --n 50` |
| 수도권 20~30대 여성 직장인 | `python scripts/make_panel.py --age 20-39 --sex 여 --region 수도권 --job 사무관리,전문기술` |
| 가격에 민감한 20대 대학생만 | `python scripts/make_panel.py --preset univ --price 중간,높음` |
| 60세 이상 기혼, 지방 거주 | `python scripts/make_panel.py --age 60- --marital 기혼 --region 기타` |
| 같은 조건으로 다른 사람들 뽑기 | 뒤에 `--seed 7`처럼 숫자만 바꾸기 |
| 결과 파일 이름 정하기 | 뒤에 `--name 데모_대학생` |

### 쓸 수 있는 조건

| 옵션 | 고를 수 있는 값 | 예 |
|---|---|---|
| `--preset` | `univ`(20대 대학생), `30s_office`(30대 사무·관리), `40s_all`(40대 전체), `60plus`(60세 이상) | `--preset univ` |
| `--age` | 만 19세 이상. `최소-최대`, `60-`는 60세 이상 | `--age 20-39` |
| `--sex` | 남, 여 | `--sex 여` |
| `--job` | 사무·관리, 전문·기술, 판매·서비스, 생산·기능, 농림어업, 학생, 무직·기타 | `--job 사무관리,판매서비스` |
| `--school` | 고졸이하, 대졸, 대학원 | `--school 대졸` |
| `--region` | 수도권, 광역시, 기타 | `--region 수도권` |
| `--marital` | 미혼, 기혼 | `--marital 미혼` |
| `--price` | 가격 민감도 낮음, 중간, 높음 | `--price 높음` |
| `--n` | 인원 (기본 100) | `--n 20` |
| `--seed` | 같은 숫자면 항상 같은 결과 (기본 42) | `--seed 7` |

- 여러 값은 **쉼표로** 잇습니다(띄어쓰기 없이).
- 가운뎃점(·)은 빼고 써도 됩니다: `사무관리` = `사무·관리`
- `--preset`과 다른 조건을 같이 쓰면 프리셋에 조건이 더해집니다.
- 전체 도움말: `python scripts/make_panel.py --help`

## 4. 실행 결과 읽는 법

실행이 끝나면 이런 줄이 나옵니다.

```
panel_custom_n50_seed42 | 50명 (요청 50) | 실제 응답자 255명 기반 | 매칭 수준 {1: 47, 2: 2, 4: 1} | 자동 점검 통과
  -> outputs/panel_custom_n50_seed42.csv
```

| 항목 | 뜻 | 괜찮은 기준 |
|---|---|---|
| 50명 (요청 50) | 실제로 만든 인원 | 요청과 같으면 OK. 적으면 `! 후보가 모자란 칸`이 함께 나옵니다 |
| 실제 응답자 N명 기반 | 조건에 맞는 미디어패널 응답자 수 | 많을수록 다양함. 수십 명 이하면 같은 습관이 반복될 수 있음 |
| 매칭 수준 {1: 47, ...} | 1 = 6개 조건(성별·연령대·직업군·학력·권역·혼인)이 모두 같은 응답자를 찾음. 숫자가 클수록 조건을 풀었음 | 3·4가 절반 이하 |
| 자동 점검 | 인원 배분, 분포, 카드 중복, 카드 속 숫자를 자동 확인 | "통과" |

`! 등급 경고`가 나오면 그 집단은 등급이 고르게 나뉘지 않았다는 뜻입니다. 예를 들어 60세 이상은 유료 서비스를
쓰는 사람이 원래 적어서 "가격에 둔감"이 12%뿐입니다. 오류는 아닙니다.

## 5. 결과 파일

`outputs/` 폴더에 3개씩 생깁니다(git에는 안 올라감).

| 파일 | 용도 |
|---|---|
| `panel_이름_n인원_seed번호.csv` | **엑셀로 열어 보는 용**. 한 줄 = 페르소나 한 명 |
| `.parquet` | 같은 내용, 코드에서 읽는 용 |
| `_report.json` | 점검 결과 상세 (검증 담당용) |

CSV에서 주로 볼 열:

| 열 | 내용 | 예 |
|---|---|---|
| `persona_id` | 페르소나 번호 | P001 |
| `age`, `sex`, `province`, `occupation` | 나이, 성별, 시도, 직업 | 21, 남, 광주, 무직 |
| `job_group` | 직업군 (7개 중 하나) | 학생 |
| `ps_grade` | 가격 민감도 (높음 = 돈 쓰기 망설임) | 중간 |
| `da_grade` | 디지털 수용도 (높음 = 새 앱에 빨리 적응) | 높음 |
| `ns_grade` | 새것 선호 | 높음 |
| `privacy_concern` | 개인정보 우려 1~5 (5 = 매우 걱정) | 2 |
| `ott_payment` | OTT 결제 방식: 단독 / 친구와 나눔 / 가족 / 미이용 | 가족 |
| `match_level` | 실제 응답자와 얼마나 정확히 짝지었나 (1이 가장 정확) | 1 |
| `card_text` | **AI에게 넣을 카드 문장 전체** | |

### 카드 뷰어로 보기

```
python scripts/make_viewer.py
```
`outputs/viewer.html`을 더블클릭하면 브라우저에서 열립니다. `outputs/`에 있는 패널이 탭으로 나오고,
등급·OTT로 거르거나 검색할 수 있습니다. 팀 공유용 링크는 맨 위 "카드 뷰어"입니다.

## 6. 담당별로 가져다 쓸 것

| 담당 | 쓸 것 | 어떻게 |
|---|---|---|
| 프롬프트 (Ask·Act) | CSV의 `card_text` | 프롬프트의 Persona 자리에 그대로 넣기. 점수 숫자는 넣지 않기 |
| 백엔드 (panel API) | `src/engine.py`의 `build_panel(target, n, seed, donor=, nv=)` | `panel/generate`에서 호출해 한 명씩 `personas.attributes_json`에 저장. 데이터 로딩은 서버 시작 때 한 번 |
| 프론트 (Panel 화면) | 3장의 "쓸 수 있는 조건" 표 | 화면의 선택지를 이 값들과 맞추기. 카드는 뷰어처럼 프로필 / 서술 / 행동 문장으로 |
| 검증 | `_report.json` | 분포 일치, 매칭 수준, 경고를 스터디 신뢰도 근거로 |
| 기획 | 3장 예시 | 데모 스터디 타깃을 조건 조합으로 정하기 |

## 7. 문제가 생기면

| 증상 | 해결 |
|---|---|
| 한글이 `???`나 깨진 글자로 나옴 | `set PYTHONUTF8=1` 후 다시 실행 |
| `FileNotFoundError ... p24v32_KMP_spss.sav` | 2장 2번: zip을 `data/raw/`에 풀었는지 확인 |
| `--job 값 오류` | 3장 표의 값으로. 오류 메시지에 쓸 수 있는 값이 나옵니다 |
| `만들 수 없습니다: 조건에 맞는 donor가 없습니다` | 조건이 너무 좁음. 연령 범위를 넓히거나 조건을 하나 빼기 |
| `! 후보가 모자란 칸` | 그 칸의 NVIDIA 페르소나가 부족함(특히 농림어업). 인원이 요청보다 적게 나옴 |
| 같은 조건인데 다른 사람이 나왔으면 좋겠음 | `--seed` 숫자 바꾸기 |

## 8. 알고 써야 할 점

- **실제 대학생 서술이 거의 없습니다.** NVIDIA에 "학생" 직업이 없어서, 서술에 구직 표현이 없는 20대 대졸 무직자를 학생으로 봅니다.
- **2024년 조사 기준**이라 OTT·생성형 AI 유료 이용이 지금보다 낮게 나올 수 있습니다.
- **자취하는 대학생의 소비가 거의 반영되지 않습니다.** 조사 대상 대학생 대부분이 부모와 함께 삽니다.
- **등급은 고른 집단 안에서의 상대값입니다.** 같은 사람도 비교 집단이 다르면 "높음"이 "중간"이 될 수 있어, 다른 스터디끼리 등급을 비교하지 않습니다.
- **농림어업 페르소나가 적어서** 고령·지방 타깃에서 인원이 모자랄 수 있습니다.
- 발표에서는 "합성 데이터 생성" 대신 **"분포 기반 페르소나 샘플링"**이라고 말합니다.

전체 한계와 점검 결과 표: `python scripts/make_readme.py` → `outputs/README.md`

## 9. 파일 지도

```
data/persona_engine/
├─ README.md               ← 지금 이 문서
├─ requirements.txt        설치 목록
├─ occupation_map.csv      직업명 1,134개 → 직업군 대응표 (팀 검토용, 엑셀로 열기)
├─ scripts/
│  ├─ make_panel.py        ★ 페르소나 만들기 (이것만 실행하면 됨)
│  ├─ make_viewer.py       카드 뷰어 HTML 만들기
│  ├─ make_readme.py       점검 결과·한계 정리 (outputs/README.md)
│  ├─ viewer_template.html 뷰어 디자인
│  └─ dev/check_step0~2.py 데이터 검증용. 원본 데이터를 바꿨을 때만 (평소엔 안 씀)
└─ src/                    엔진 내부 (고칠 일이 있을 때만)
   ├─ config.py            설정값: 경로, 가격 민감도 가중치, 등급 기준
   ├─ engine.py            핵심: 인원 배분 → NVIDIA에서 뽑기 → 실제 응답자 짝짓기
   ├─ donor.py             미디어패널 읽기, 점수 계산
   ├─ nvidia.py            NVIDIA 읽기, 직업 → 직업군 사전
   ├─ cards.py             카드 문장 만들기 (문장 표는 여기)
   ├─ checks.py            자동 점검
   └─ utils.py             공용 계산 함수
```

자주 고칠 만한 곳:

- 새 프리셋 추가 → `scripts/make_panel.py`의 `PRESETS`
- 카드 문장 바꾸기 → `src/cards.py` 위쪽의 문장 표 (Ask·Act 프롬프트와 공유하므로 팀 합의 후)
- 직업 분류 고치기 → `src/nvidia.py`의 `OCC_EXACT`(직업명 하나씩) 또는 `JOB_KEYWORDS`
- 가격 민감도 가중치 → `src/config.py`의 `WTP_WEIGHTS` (바꾸면 `SCORING_VERSION`도 올리기)

설계 상세(왜 이렇게 만들었는지)는 `docs/PERSONA_ENGINE_SPEC.md`에 있습니다.
