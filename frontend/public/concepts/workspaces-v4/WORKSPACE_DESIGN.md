# Editorial workspace — 2026-11-05

사용자 정정: D1~D4의 기능을 워크스페이스에 배치하라는 뜻이 아니라, 독특한 시각 디자인을 사용해 워크스페이스 첫 화면을 다시 만든다.

별도 진입점은 workspace.html이다. 기존 D1~D4와 실제 로그인 앱, 기존 프로젝트 시안은 보존한다.

시각 방향:
- D 시안의 Pretendard, 따뜻한 흰색, 갈색 포인트와 손그림 밑줄을 이어받는다.
- 큰 한국어 문장과 여백, 비대칭 헤더, 새로운 작업을 여는 종이형 버튼.
- 카드 그리드 대신 큰 번호와 구분선으로 프로젝트를 펼치는 작업 노트형 목록.
- 각 프로젝트의 마지막 테스트와 다음 작업을 오른쪽 여백에 배치한다.
- 고정 사이드바, 검은 상단바, 떠 있는 비교 바, 가짜 점수나 장식 그래프는 사용하지 않는다.

동작은 ../project-workspace/workspace.js의 프로젝트/테스트/실행 예시 모델을 appearance=editorial 옵션으로 재사용한다. 기존 렌더 경로에는 영향을 주지 않는다. 검색, 즐겨찾기, 정렬, 프로젝트/테스트 생성, 실행 기록으로의 이동을 지원한다. 원본 카드·DB·API·LLM·인증 저장소에는 연결하지 않는다.

검증: 기본/새 디자인 경로의 데이터 이동, 검색/정렬/생성/빈 상태와 입력 이스케이프를 검사한다. 브라우저 도구가 연결되지 않으면 화면 캡처 검증 한계를 명시한다.
검증 결과:
- 기존 기본 경로와 editorial 경로 모두 프로젝트 표시, 검색 포커스, 즐겨찾기, 빈 상태, 생성, 경로 이동, 입력 HTML 이스케이프 검사 통과.
- 기존 경로의 레퍼런스 3개와 새 경로의 D1~D4 참조 4개를 구분해 확인.
- 외부 API 호출 0, 기존 인증 저장소 보존 확인.
- JS 문법, 새 CSS 226개 노드 파싱 통과.
- 새 HTML/CSS/JS, D 비교 페이지와 D1~D4 원본, 공유 모델 JS 모두 로컬 HTTP 200 확인.
- 브라우저 도구의 연결 제한으로 실제 화면 캡처·반응형 렌더 검증은 수행하지 못함. 다른 브라우저 자동화로 우회하지 않음.

## 일상 사용을 위한 밀도 조정 — 2026-11-05

사용자 피드백 반영:
- 감성 문구와 손그림 디테일, 프로젝트별 마지막 작업 문맥은 유지한다.
- 기본 소개 높이를 줄이고, 소개 접기/펼치기를 제공한다. 프로젝트 4개 이상이면 자동으로 접으며 명시적 사용자 선택이 우선한다.
- 새 프로젝트 CTA를 sticky 상단 메뉴에 추가해 소개를 접거나 스크롤해도 접근할 수 있게 한다.
- 큰 대시보드 카드 대신 목록 제목 옆에 작은 요약을 둔다. 현재 예시 모델에서 계산 가능한 누적 완료 실행 수와 설정이 필요한 테스트 수만 표시한다.
- 날짜 범위별 완료 시각과 심각도 기준이 없는 현재 모델로 주간 완료/크리티컬 피드백을 만들지 않는다. 값을 0으로 오인 표시하지 않는다.
- 요약 숫자를 누르면 해당 실행/테스트를 펼쳐 실제 항목과 연결한다.
- 이전 디자인은 scratch/editorial-density-before에 보관한다. 실제 앱/DB/LLM은 수정하지 않는다.
밀도 조정 검증 결과:
- 기본 디자인 경로에는 생성 CTA/소개 접기/요약을 삽입하지 않았음을 확인.
- 직접 접기/펼치기, aria-expanded/hidden, 토글 후 포커스 유지, 접힌 상태의 상단 생성 버튼 동작 확인.
- 예시의 누적 완료 5회/이어갈 테스트 3개 집계를 확인. 완료 목록 5건과 다음 작업 3건이 실제 예시 객체로 연결됨을 검사.
- 빈 상태의 요약은 0/0이며 조회 시 비어 있음 안내 확인.
- 프로젝트 4개부터 자동 접힘, 명시적으로 펼친 뒤 5개로 늘어나도 선택을 유지함을 확인.
- 프로젝트 생성과 입력 이스케이프, 검색 포커스, 기존 인증 저장소 보존과 외부 API 호출 0 검사 통과.
- JS 문법, CSS 286개 노드 파싱, 새 진입점/자산 HTTP 200 확인.
- 화면 캡처 및 스크롤/반응형 시각 검증은 기존 브라우저 도구 연결 제한으로 수행하지 못함.
