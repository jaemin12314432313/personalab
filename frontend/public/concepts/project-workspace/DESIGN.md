# Project-first workspace — 2026-11-05

사용자가 승인한 별도 디자인 시안. 기존 B의 짙은 상단 맥락을 유지하면서 첫 화면의 중복 정보를 제거한다.

정보 구조: 프로젝트(제품/서비스 묶음) → 테스트(살펴볼 사용 경험) → 실행 기록(수정 후 반복 탐색). 프로젝트는 이번 시안의 프론트엔드 가상 컨테이너이며 실제 DB/Study 계약을 변경하지 않는다.

첫 화면은 프로젝트 제목, 검색/즐겨찾기/정렬, 두 개의 예시 프로젝트로 구성한다. 각 프로젝트는 마지막 작업 한 건과 다음 행동만 표시한다. 큰 인사말, 반복된 이어하기·최근 완료 카드, 장식용 화면 미리보기, 고정 사이드바, 떠 있는 비교 툴바를 두지 않는다.

프로젝트 내부에서는 테스트 목록과 전체 실행 기록 탭을 제공한다. 테스트 내부에서는 같은 흐름의 실행 회차를 보관하고 새 실행 설정을 추가하며 두 회차의 조건을 비교한다. 실행 상세는 일시적인 오른쪽 패널로 연다.

기본 글꼴은 기존 Pretendard Variable이다. Graphite 상단, 흰색 작업면, 본문 14~16px, 제목 32px, 상태 12px를 기준으로 한다. 비교 시안의 명칭과 데이터 출처는 하단에만 표시한다.

데이터는 모두 가상 디자인 예시이며 원본 페르소나·API·LLM·실계정 저장소를 읽거나 변경하지 않는다. 인물 사진이 필요한 곳은 기존 공개 랜딩의 AI 생성 초상만 사용한다. 새 프로젝트/테스트/실행은 로컬 메모리에서만 추가하고 실제 유료 실행을 만들지 않는다. 실제 결과 체험은 기존 공개 샘플로 연결한다.

검증 계획: JS/CSS 파싱, 로컬 HTTP, 프로젝트 검색/즐겨찾기/정렬, 생성 입력 이스케이프, 프로젝트→테스트→실행 이동, 새 실행 조건 재사용, 조건 비교, 빈 상태. 브라우저 자동화의 현재 URL 확인 제한이 풀리지 않으면 화면 검증의 한계를 그대로 기록한다.
## 검증 결과

- JS 문법 및 CSS 301개 노드 파싱 통과. HTML/CSS/JS 로컬 HTTP 200 확인.
- 프로젝트 2개 표시, 검색 입력 포커스 유지, 즐겨찾기 필터, 정렬과 목록 전환 검사 통과.
- 프로젝트 내 테스트/전체 실행 탭과 테스트 상태 필터 검사 통과.
- 테스트 내 과거 실행 유지, 새 실행 추가, 이전 페르소나 수 재사용, 화면 수 수정, 실행 조건 비교 검사 통과.
- 완료한 회차에는 수정 폼이 없음을 확인.
- 빈 워크스페이스 → 프로젝트 → 테스트 → 첫 실행 생성과 HTML 이스케이프 검사 통과.
- 공개 초상 5개 표시, 실제 fetch 호출 0, 기존 인증 localStorage 보존 확인.
- 브라우저 도구의 inventory에서 browser access host unavailable 반환. 앱/브라우저 UI 조작을 추가로 시도하지 않았고 실제 화면 캡처와 반응형 렌더 검증은 완료하지 못함.
